# Manual validation enrollment

Use `Jenkinsfile.ci-enrollment` in a separate manual job. Set exactly one SCM branch spec to the full reviewed commit SHA, set `EXPECTED_SHA` to the identical SHA, and explicitly set `TEST_ONLY=true`. Empty/mixed/branch-name configuration fails; every accepted run executes all checks. Keep Actions disabled. No job or execution is established by this source change.

The lane requires a non-root `linux-native` executor with Git and Docker Pipeline/container access. Node tests run in `node:22-bookworm` without host Node provisioning. `oven/bun:1.3.3-debian` must be pullable and support Git and the executor's numeric UID. Each container has a one-minute preflight verifying its actual checkout SHA and tool availability. These operational prerequisites require a live validation; labels alone are not evidence. Checkout and workspace deletion occur on the host outside the container. No toolchains are provisioned on the host.

Required checks are the original release-branch tests, additional pure release-plan/cleanup and shell-runner regression tests, dependency installation, and mandatory Bun compilation of `server/src/index.ts`. Installation must leave a nonempty SDK package manifest; compilation must create a new nonempty `index.js` after stale output removal. Original `tsc --noEmit` remains advisory (the package supplies no `tsc` script). The original advisory import is deliberately replaced with compilation: executing the app opens ngrok and starts phone/MCP services. Installation disables project lifecycle scripts; the Bun version is fixed at locally checked 1.3.3 rather than the old floating latest. These are explicit safety differences from the original workflow.

Node test processes use an empty inherited environment except PATH and Git configuration isolation flags; user/system Git configuration is disabled. Bun runs in a disposable non-root container with an empty environment except PATH, explicit empty npm/Bun configuration, local caches, and automatic `.env` loading disabled. No host home is mounted or HOME overwritten, no provider credentials are bound, and no application runtime, tag, release, issue, registry, R2 or deployment operation is called. Source dependencies must still be reviewed before enrollment. The release readiness gate requires release-event metadata and is exercised by its pure plan/source tests; this test-only lane does not claim release readiness or produce release artifacts. Existing CI and release behavior is unchanged.

Shell files under `scripts/ci/` are stored and checked out with LF via a scoped
`.gitattributes` rule. The runner tests reject carriage returns and execute its
actual bytes using `/bin/sh` on Linux or Git for Windows dash on Surface. This
avoids relying on Bash's platform-specific CRLF handling or checkout autocrlf.
